### Translation generator (run 2, at Luis's request, about 15:05 UTC)
- Luis asked to treat English as the only source and to regenerate every other language with an LLM instead of translating by hand.
- New `scripts/i18n-generate.mjs` and npm script `i18n:generate`. For each namespace (`locales`, `locales-newflow`, `locales-dashboard`, `locales-billing-form`, `locales-subscribe`) and each language file in its folder, it flattens `en.ts` into text items keyed by JSON pointer, sends the untranslated ones in chunks (default 40 items or 5000 characters) with a prompt that explains the product, the screen family, the language and why, checks the answer has exactly the same keys and placeholders, appends it to `i18n-cache/<namespace>/<locale>.jsonl`, and rebuilds `<locale>.ts` with the exact shape of `en.ts`. The LLM produces values only. URLs, app paths, ids and numbers are copied from English. Unused sections in `scripts/i18n-unused.json` are skipped.
- Resumable: the cache is append-only and keyed by a hash of the English text, so a stopped run continues, and a changed English string is sent again on its own. A bad answer is retried 3 times, then the chunk is split in half; a single item that keeps failing stays English.
- Providers: OpenAI (default, `gpt-4.1-mini`), Gemini, OpenRouter, Anthropic or any OpenAI-compatible URL through `I18N_LLM_*` variables; `echo` for a free end-to-end test.
- Tested on a scratch copy: `--dry-run` (118,774 items, about 3,100 requests over 334 files), `echo` run for es, ar, de (i18n-check 100%, second run sends nothing), and a mock provider that answered with non-JSON, a missing key and broken placeholders (retries, split, then complete; dashes cleaned). `npm run build` passes with generated files.
- The current non-English files were not deleted (the first real run overwrites them). Not run against a real provider: no key in this session.
